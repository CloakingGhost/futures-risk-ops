# ADR 0001. 쿠버네티스는 클라우드가 아니라 PC 안의 k3d 로 돌린다

- 상태: 확정
- 날짜: 2026-11-16 (Day 7)

## 배경

collector 와 risk 는 컨테이너 이미지(Day 4 Dockerfile)로 묶여 있고, Day 8 부터 DB 와 함께 쿠버네티스에서 돌린다.
이 저장소는 사용자가 자기 키로 자기 PC 에서 실행하는 셀프 호스팅만 한다(루트 CLAUDE.md). 시세를 남에게 다시 보여 주는 중앙 서버가 없다.
쿠버네티스를 쓰는 목적은 서비스를 공개하는 것이 아니라 배포·재시작·헬스 체크·자원 제한을 코드(Helm 차트, 클러스터 설정)로 다시 만들 수 있게 하는 것이다.

제약:

- 비용이 들지 않아야 한다. 학습·검증용이라 상시 켜 둘 이유가 없다.
- 지웠다 다시 만들어도 같은 상태가 나와야 한다(`deploy/k3d/up.sh`, `down.sh`).
- collector 는 KIS 접속이 하나라서 **한 번에 하나만** 떠야 한다. 클러스터가 collector 를 둘 띄우는 일이 없어야 한다(차트가 replicas 1, Recreate 로 막는다).
- 키는 환경변수로만 읽는다. 클러스터 밖(인터넷)에 서비스를 열지 않는다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 클라우드 관리형 쿠버네티스(EKS, GKE, AKS 등) | 실제 운영과 같은 환경 | 제어 영역·노드·로드밸런서에 시간 단위 요금이 든다(가정: 직접 요금표를 확인하지 않음). 켜 두면 계속 나가고 끄면 상태가 사라진다. 공개 엔드포인트와 인증을 새로 다뤄야 한다. 이 저장소의 셀프 호스팅 범위 밖이다 |
| kind | Docker 안에 쿠버네티스를 띄우고 설정 파일로 만든다 | 가볍지만 기본 구성이 크다. k3s 처럼 작은 배포판은 아니다(가정: 직접 비교하지 않음) |
| minikube | 가장 널리 알려져 있고 자료가 많다 | 드라이버(VM·Docker)에 따라 동작이 달라지고, 설정 파일 하나로 재현하는 흐름이 상대적으로 약하다(가정) |
| **k3d** | k3s(가벼운 배포판)를 Docker 컨테이너로 띄운다. 설정 파일 하나로 만들고 지운다. 저장소(local-path)가 기본 포함이라 Day 8 DB 의 PVC 가 그대로 된다. `k3d image import` 로 레지스트리 없이 이미지를 넣는다 | 이 PC 에서만 확인한 것이라 클라우드의 로드밸런서·다중 노드 장애는 검증되지 않는다. 설치할 도구가 하나 는다 |

## 결정

**k3d 로 PC 에 클러스터를 만든다.** 비용은 0원이다(전기와 PC 자원 제외).

- 서버 1, 에이전트 0, Traefik 끔, 쿠버네티스 API 는 `127.0.0.1:6550` 에만 연다(`deploy/k3d/cluster.yaml`).
- k3s 이미지는 `rancher/k3s:v1.32.5-k3s1` 로 고정한다. 이유: k3d 기본 이미지는 이 PC 에서 v1.35 였고 시간이 지나면 바뀐다. kubectl 은 서버와 마이너 버전이 ±1 까지만 지원되는데 이 PC 의 kubectl 은 v1.32 라서 같은 마이너로 맞췄다.
- 이미지는 레지스트리 없이 `k3d image import` 로 넣는다(`up.sh --import`). GHCR 푸시는 Day 11 CI 로 미룬다.
- 클러스터에는 앱을 설치하지 않는다. Day 8 에 DB StatefulSet 과 Helm 배포를 한다.

## 결과

이 PC(Docker 메모리 약 14.5GB, CPU 16)에서 2026-11-16 에 확인한 값이다.

| 항목 | 값 |
|---|---|
| 처음 만들기(이미지 내려받기 포함) | 34초 |
| 지우기 | 2초 |
| 지운 뒤 다시 만들기(이미지 캐시됨) | 19초 |
| 지웠다 다시 만든 뒤 상태 | 노드·파드·네임스페이스·스토리지클래스가 같다 |
| 빈 클러스터의 서버 컨테이너 메모리 | 약 455MiB |
| 바깥에 열린 포트 | 쿠버네티스 API `127.0.0.1:6550` 하나뿐 |

- 도구는 winget 으로 설치했다(helm 4.3.2, k3d 5.9.0). 설치 과정과 부딪힌 문제는 [docs/ops-log/2026-11-16-k8s-tools-install.md](../ops-log/2026-11-16-k8s-tools-install.md).
- 같은 PC 에서 collector 를 compose 와 클러스터에 동시에 띄우면 KIS 접속이 둘이 된다. Day 8 에 클러스터 collector 를 띄우기 전에 compose collector 를 끈다.
- 단점은 여전하다: 이 환경은 로드밸런서·다중 노드·클라우드 저장소를 검증하지 않는다. 필요해지면 새 ADR 로 다시 정한다.
