# 남은 일과 확인 안 된 가정

마지막 갱신: 2026-11-17 (Day 7). 해소된 것은 맨 아래 '해소됨'에 날짜와 함께 옮겼다.

## 확인 대기 (2026-11-17 안에 끝난다)
- 16:00 일봉 스케줄이 실제로 도는지(타이머 경로는 테스트로 확인함).
- 일봉(F)을 주간장 기준으로 볼 수 있는지: 11/17 F 일봉과 그날 KIS 체결 비교(종가 일치 + 거래량 차이 1% 이내). 낮 동안 collector 를 재시작하지 않는다. 수집 구멍으로 결론이 안 나면 하루 더.
- 확정 시점(마감 15분 뒤 값이 이미 확정인지): 16:05 스냅샷 vs 23시 이후 재수신. 그때 이미지를 다시 빌드해 재시작한다(토큰 만료 수정 포함).

## 사용자가 확인하거나 정할 것
- **야간장 체결의 거래일 규칙**(`night_trade_date: next_trading_day` 가정). 현상 유지, 사용자가 실제 앱 화면과 해석을 보내 주기로 했다. 미결제 일별 변화 API 가 이 값으로 묶어서 규정이 틀리면 야간 정보가 하루 어긋난다. **화면 이미지에 실제 시세 값이 보이면 프롬프트에 붙이지 않는다**(루트 CLAUDE.md). 날짜·거래일 표시 부분만 잘라 보내거나 가격을 가린다. 저장소에 올리지 않는다.
- 증거금률 정기 점검: **2026-12-07**(12월 첫 월요일). 값을 확인하면 `risk/application.yml` 과 `docs/history/margin-rates.md` 를 고친다.
- 주식선물(SK하이닉스, 삼성전자 등) 추가 예정 → 상품별 증거금률이 필요하다.
- 지수 테이블을 둘지: 장단점을 쉬운 설명으로 들은 뒤 사용자가 정한다(미정).

## 확인 안 된 가정
- 주간 1~4계약 빈틈이 KIS 묶음 전송 때문이라는 것.
- 체결 메시지 12~14번 `mrkt_basis` = 선물 − 지수.
- KIS 일봉의 종가 필드(현재가)가 과거 일자에서 그날 종가라는 것(11/2·11/3 은 모의투자 체결과 일치, 부분 확인).
- 야간 거래일 귀속이 KRX 규정과 같다는 것(위 '사용자가 확인할 것').
- 휴장일 YAML: 2026 연말·2027 연초(`2026-12-25`, `2026-12-31`, `2027-01-01`)는 가정이다. 2027 년 전체로 늘리고 KRX 공지로 확인한다.
- 2026 수능(11/19) 주간장 시간 변경(개장·마감 1시간 늦춤)은 가정이다(Day 24 에 KRX 공지로 확인).
- `mod_yn`(일봉 변경 여부)의 뜻: KIS 전체 문서에도 없다. 값만 보관하고 쓰지 않는다.
- 모의투자(`kis-paper`)가 일봉을 주는지: 문서상 지원, 쓰지 않아 미확인.

## v0.1 에서 하지 않기로 한 것
