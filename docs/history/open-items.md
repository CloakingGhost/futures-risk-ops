# 남은 일과 확인 안 된 가정

마지막 갱신: 2026-11-19 (Day 8·9). 해소된 것은 맨 아래 '해소됨'에 날짜와 함께 옮겼다.

## 사용자가 확인하거나 정할 것
- **Windows 업데이트를 중지했다(사용자, 2026-11-17)**: 05:08 자동 재시작으로 collector 가 죽은 일([../ops-log/2026-11-17.md](../ops-log/2026-11-17.md))을 막으려고 사용자가 업데이트를 아예 중지했다. 보안 업데이트가 쌓이므로 언제 다시 켜고 어떻게 적용할지(예: 장이 닫힌 시간에 수동으로, collector 를 끄고) 정해야 한다. Day 8 의 '파드 재시작 0회'·운영 시작 기록과 관련된다.
- compose 서비스에 `restart: unless-stopped` 를 넣을지(Docker 가 다시 켜지면 collector 도 자동으로 올라온다). 지금은 재시작 정책이 없어 Docker 가 꺼졌다 켜져도 compose 컨테이너는 멈춘 채로 남는다. k3d 컨테이너는 재시작 정책이 있어 스스로 올라왔다. Day 8 에 클러스터로 옮기면 파드는 스스로 다시 뜬다.
- **야간장 체결의 거래일 규칙**(`night_trade_date: next_trading_day` 가정). 현상 유지, 사용자가 실제 앱 화면과 해석을 보내 주기로 했다. 미결제 일별 변화 API 가 이 값으로 묶어서 규정이 틀리면 야간 정보가 하루 어긋난다. 화면 이미지의 실제 시세 값은 프롬프트에 붙여도 된다(2026-11-19 사용자 결정, 루트 CLAUDE.md). 키·계좌번호가 보이면 가린다. 저장소·공개 게시물에는 올리지 않는다(절대 규칙 3).
- 증거금률 정기 점검: **2026-12-07**(12월 첫 월요일). 값을 확인하면 `risk/application.yml` 과 `docs/history/margin-rates.md` 를 고친다.
- 주식선물(SK하이닉스, 삼성전자 등) 추가 예정 → 상품별 증거금률이 필요하다.
- 지수 테이블을 둘지: 장단점을 쉬운 설명으로 들은 뒤 사용자가 정한다(미정).

## 확인 안 된 가정
- **마감 뒤 유지 10초의 값**: 관찰 3건(도착이 마감 정각보다 0.2~1.6초 빠름)에서 정했다. 관찰 4건 모두 도착이 정각보다 0.2~1.6초 빨랐다(2026-11-19 06:00 은 0.7초). 며칠 더 보고 놓친 마감 체결이 없는지 본다(일봉 비교 쿼리의 `close_matches`).
- 마감 뒤 유지 구간(06:00:01~06:00:10)에 호가가 오면 시각대로 분류돼 DAY 로 쌓인다(체결은 마감 정각 뒤에 오지 않는다고 가정). 호가는 risk 가 읽지 않아 영향이 작다. 야간은 호가 TR 을 구독하지 않아 해당이 없다(2026-11-19 확인, 0건). 주간 마감(15:45) 뒤 구간은 2026-11-19 낮에 확인한다.
- **재접속으로 놓친 체결을 KIS 에서 다시 받는 방법**: 확인하지 못했다. 2026-11-18 밤에 PC 를 옮기며 접속이 두 번 끊겨 11/19 야간 거래량의 약 6.7% 를 놓쳤다([../ops-log/2026-11-19.md](../ops-log/2026-11-19.md)). 놓친 구간은 누적거래량 빈틈으로 알 수 있지만 체결 자체는 되살리지 못한다.
- 일봉 거래량이 실시간 체결의 마지막 누적거래량보다 날마다 0.6~2.7% 큰 이유(원인 미상, 야간 합산은 아님). 후보: 실시간 체결에 오지 않는 거래, 집계 정의 차이.
- 접근토큰 만료·무효를 알리는 오류 코드 `EGW00121`·`EGW00123`: KIS 공식 문서(로컬 전체 문서)에 없고 경험적으로 알려진 값이다.
- **알람 ⑤ 노드 디스크 80%**: k3d 노드(Docker 컨테이너) 안에서 node-exporter 가 실제로 어떤 마운트를 보는지 확인하지 못했다. `overlay` 를 제외하는 필터라 컨테이너 루트가 overlay 뿐이면 조용히 안 울릴 수 있다. `local-path` PVC 용량 지표는 다루지 않았다([day8-day9.md](day8-day9.md)).
- Grafana 화면(브라우저)에서 대시보드 4개가 의도대로 보이는지, Loki 보존 72시간이 실제로 지워지는지(설치 3일 뒤)는 확인하지 못했다. 쿼리 42개는 API 로 확인했다(OK 40, EMPTY 2 정상, ERROR 0).
- KIS 카카오톡 '접근 토큰이 발급되었습니다' 안내는 collector 가 토큰을 받는 시각으로 옮겨 간다고 예상한다(2026-11-19 14:24 발급, 만료 11/20 14:24). 11/20 14:24 전후에 오는지로 확인한다.
- 주간 1~4계약 빈틈이 KIS 묶음 전송 때문이라는 것.
- 체결 메시지 12~14번 `mrkt_basis` = 선물 − 지수.
- KIS 일봉의 종가 필드(현재가)가 과거 일자에서 그날 종가라는 것(11/2·11/3 은 모의투자 체결과 일치, 부분 확인).
- 야간 거래일 귀속이 KRX 규정과 같다는 것(위 '사용자가 확인할 것').
- 휴장일 YAML: 2026 연말·2027 연초(`2026-12-25`, `2026-12-31`, `2027-01-01`)는 가정이다. 2027 년 전체로 늘리고 KRX 공지로 확인한다.
- 2026 수능(11/19): 주간 09:45~16:45, 야간 19:00 개장(마감 06:00 은 평소)으로 설정했다. 근거는 2026-11-05 보도(사용자가 2026-11-17 에 알려 줌)이고 **KRX 원문 공지는 확인하지 못했다**. 11/19 collector 로그의 접속·수신 시각으로 맞는지 본다.
- `mod_yn`(일봉 변경 여부)의 뜻: KIS 전체 문서에도 없다. 값만 보관하고 쓰지 않는다.
- 모의투자(`kis-paper`)가 일봉을 주는지: 문서상 지원, 쓰지 않아 미확인.
